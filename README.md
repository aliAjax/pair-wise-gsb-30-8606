# 油品配送 · 油库装车可恢复流程

- 行业：石油
- 技术栈：Vue3、Vite、TypeScript、Pinia
- 启动：`npm install && npm run dev`
- 构建：`npm run build`
- 核心流程冒烟测试：`npm run smoke`（30 项断言：竞争/恢复/差异门禁/证件重算）

数据保存在浏览器 localStorage（键 `hxwlfront-19-oil-flow-v2`），WAL 与业务数据一起持久化，
刷新页面后未完成的中断事务仍可断点恢复。

## 业务闭环

配送单状态机：

```
待确认 ──确认(按油品预占罐容)──▶ 已预占 ──皮重+毛重回执到齐核销──▶ 已核销/差异待复核
                                  │                                  │
                                  │                       差异未复核不能发车
                                  │                                  │ 人工复核
                                  ▼                                  ▼
                          （证件过期）待重算 ◀──失效重算            已发车 ──依据冻结
```

关键规则：

1. **确认前按油品预占罐容**：选车时只列出具备对应油品舱、舱容≥计划吨数的罐车；确认后生成
   `预占` 占用记录，锁定该油品舱容量，证件过期司机不能确认。
2. **回执到齐后核销**：皮重（车自重）+ 毛重（总重）两张回执都登记后才能核销，净重 = 毛重 − 皮重，
   占用转为 `核销` 并计算差异；回执不齐/净重异常拒绝核销。
3. **差异未复核不能发车**：差异超容差（默认 ±0.1 吨）进入「差异待复核」，发车门禁拦截；
   人工复核通过后才允许发车。发车后占用、回执、差异依据**随单冻结**，罐车装车位释放可接新单。
4. **两窗口同时提交只放行一单**：窗口锁（内存）+ 占用记录（持久化）双重互斥，失败方记
   「窗口竞争失败」审计，不写入任何占用。
5. **写入失败从中断点恢复**：事务按步骤执行，每步先记 WAL 再落库；注入写入故障时该步回滚、
   WAL 标记断点（`failedStep`）。恢复时跳过已完成步骤、幂等重放断点步骤，**不重复占车**。
6. **司机证件过期**：证件核查以核查日为准——
   - 未发车单：占用 `失效`、未核销回执作废、差异清零，退回「待重算」，需重新选车预占；
   - 已发车单：占用/回执/差异原依据全部保留，不重算。

## 列表与审计

- 配送单卡片展示：占用 ID 与预占→实装吨数、地磅差异与复核状态、证件失效后的重算范围。
- 审计面板可按动作类型/关键字过滤，每条记录含「影响范围」，明确占用、差异、回执的波及面。
- WAL 面板实时显示每个事务的步骤完成情况（✓ 已落库 / ✗ 断点）与状态。

## 演示路径

1. 右栏「双窗口竞争」选择 `PS-20261001-03` 与任意罐车 → 两窗口同时提交，只见一单放行；
   勾选「首单写入制造故障」可再演练：两单均不放行 → 点「从中断点恢复」→ 只产生一条占用。
2. 中间列表对已预占单登记皮重/毛重（如皮重 12、毛重 22.5 → 净重 10.5，计划 9 → 差异 +1.5），
   核销后尝试发车被拦，复核差异后放行。
3. 左栏「油罐车与证件核查」：对 `京A·油1002` 点「模拟证件过期」→ 执行核查，
   观察 `PS-20261001-02` 占用失效、回执作废、退回待重算；
   已发车的 `PS-20261001-01`（该车司机也已过期）原依据保留。

## 目录

- `src/workflow/types.ts`：领域模型与错误类型
- `src/workflow/engine.ts`：步骤化事务定义（预占/核销/复核/发车/重算/证件调整）、窗口锁
- `src/workflow/seed.ts`：初始车辆、舱容、配送单演示数据
- `src/workflow/store.ts`：Pinia store、WAL 写入/回滚/断点恢复、持久化
- `src/components/`：配送单卡片、建单表单、罐车面板、竞争/恢复演练、审计面板
- `scripts/smoke.mjs`：核心流程无浏览器冒烟测试
